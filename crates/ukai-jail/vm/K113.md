# Warm-VM Claude compatibility measurements

`claude_vm_row.py` measures an installed client and guest. It does not change
capabilities, bypass `vm:not-measured` refusals, or mark K113 supported. Its
original four positional arguments still measure the single marker/transport
lane; that lane's `PASS` is not a complete compatibility verdict. Every record
now says `qualified=false` and `compatibility_outcome=UNMEASURED`.

The compatibility matrix adds the A01 greeting fixture, a small code/test task
in that repository, ten A01 repetitions in fresh repositories, and a missing
credential-source control. Each lane has a new output directory. Failures and
progress records are retained; there is no automatic retry that hides a failure.
The small task's tests execute inside the guest, and the host checks that the
test file was not modified. Host execution of agent-written code is not used.

Stage the existing pinned Linux ARM64 Claude Code executable in a dedicated
workspace marked by `harness.py mark`. Supply the installed root and its shipped
client, not a repository-built replacement. For the explicit API-key mode:

```sh
python3 crates/ukai-jail/vm/claude_vm_row.py \
  /path/to/installed-root /path/to/marked-workspace /path/to/new-evidence \
  /path/to/installed-root/bin/ukai-jail \
  --credential-kind api-key --credential-source /path/to/private/anthropic \
  --compatibility
```

The harness reads that selected file only during an invoked live lane. It
requires an owned private regular file with one link, refuses symlinks, bounds
the read, and checks for changes while reading. It copies the value to a private
single-use source outside the workspace, puts only the path in profile data,
and deletes the copy before stopping the VM, including on failure. It preserves
the operator's source. An API key uses `ANTHROPIC_API_KEY` and `x-api-key`; OAuth
uses `CLAUDE_CODE_OAUTH_TOKEN` and `Authorization: Bearer`. The missing-source
lane reads neither credential. It passes only the matching resolving-stage
credential refusal with its hint and no attempt/workload; a capability refusal
is not a missing-source pass. No secret is passed in argv or printed.

Individual added lanes can be selected with `--case a01`, `--case small-task`
or `--case missing-source`. The default OAuth mode keeps the prior keychain/file
selection and expiry margin; an explicit OAuth source may instead be supplied.
An explicit source's expiry is not inferred from its bytes.

The new per-run compatibility checks require strict observation, all six active
classes without gaps, verified tree settlement and cleanup, one never-staged
vault credential, and agreement between text and JSON summaries. Exact use
counts require the guest's proxy journal; the host lifecycle journal is never
substituted for it. Current VM transport exports no guest journal and the
summary reports guest counts unavailable, so this condition remains unmet.

The whole matrix returns nonzero and can be only `FAIL` or `UNMEASURED` in this
implementation. Mid-stream host-source revocation has no demonstrated guest
propagation, full independent summary recomputation and sampled environments
remain outstanding, and the explicit workspace executable does not demonstrate
Linux alias-derived executable grants. Installed/notarized candidate acceptance
is separate. These limitations are retained in the report; synthetic tests do
not retire them or promote K108–K113.

```sh
cd crates/ukai-jail/vm
python3 -m unittest test_claude_vm_compatibility test_harness_rows.ClaudeRowTests -v
```
