# Warm-VM Claude compatibility measurements

`claude_vm_row.py` measures an installed client and guest. It does not change
capabilities, bypass `vm:not-measured` refusals, or mark K113 supported. Its
original four positional arguments still measure the single marker/transport
lane; that lane's `PASS` is not a complete compatibility verdict. Every record
now says `qualified=false` and `compatibility_outcome=UNMEASURED`.

## Catalog-native API-key measurement

The separately admitted catalog-native route uses the unchanged bundled launch
profile and executable. It requires an installed matching image, explicit
attempt state, detached terminal, closed stdin and a case-sensitive marked
workspace. The [guest-native contract](GUEST-NATIVE.md) defines that scope.
For one bounded API-key task:

```sh
python3 -B crates/ukai-jail/vm/claude_vm_row.py \
  /path/to/installed-root /path/to/marked-workspace /path/to/new-evidence \
  /path/to/installed-root/bin/ukai-jail \
  --execution-mode guest-native --credential-kind api-key \
  --credential-source /path/to/private/anthropic --case a01 \
  --native-api-bounds --api-model sonnet --api-max-budget-usd 0.25
```

Run the `--case missing-source` control first, omitting `--credential-source`.
It must refuse with both bundled source hints and create no workload. The
bounded lane accepts only one `a01`, `small-task` or `missing-source` case;
it refuses `--compatibility` and OAuth. It requests the pinned vendor CLI's
`--bare`, `--no-session-persistence` and `--max-budget-usd` options, with a
240-second wall limit and closed stdin. The requested dollar amount is a vendor
budget setting, not an independently enforced billing ceiling. The report
retains typed vendor-reported model usage and cost and refuses an over-budget
reported cost. No maximum-turn option is assumed.

Inspect each result before scheduling another task. A pass requires the actual
task output, exact program-derived grants, bound guest receipts and full
journal, independently recomputed summaries, complete periodic observations of
the exact receipt workload, clean exports and verified cleanup. Sampling has
the limited environment/argv scope documented in the guest-native contract;
it does not establish absence from process memory or between samples. The
operator's original credential source remains unchanged; only a private test
copy is removed. A single API-key pass does not qualify OAuth, vendor-stream
revocation, the full ten-task matrix or K113.

## Original workspace-executable matrix

The compatibility matrix adds the A01 greeting fixture, a small code/test task
in that repository, ten A01 repetitions in fresh repositories, and a missing
credential-source control. Each lane has a new output directory. Failures and
progress records are retained; there is no automatic retry that hides a failure.
The small task's tests execute inside the guest, and the host checks that the
test file was not modified. Host execution of agent-written code is not used.

Stage the existing pinned Linux ARM64 Claude Code executable in a dedicated
workspace marked by `harness.py mark`. Supply the installed root and its shipped
client, not a repository-built replacement. For the explicit API-key mode:

```sh
python3 crates/ukai-jail/vm/claude_vm_row.py \
  /path/to/installed-root /path/to/marked-workspace /path/to/new-evidence \
  /path/to/installed-root/bin/ukai-jail \
  --credential-kind api-key --credential-source /path/to/private/anthropic \
  --compatibility
```

The harness reads that selected file only during an invoked live lane. It
requires an owned private regular file with one link, refuses symlinks, bounds
the read, and checks for changes while reading. It copies the value to a private
single-use source outside the workspace, puts only the path in profile data,
and deletes the copy before stopping the VM, including on failure. It preserves
the operator's source. An API key uses `ANTHROPIC_API_KEY` and `x-api-key`; OAuth
uses `CLAUDE_CODE_OAUTH_TOKEN` and `Authorization: Bearer`. The missing-source
lane reads neither credential. It passes only the matching resolving-stage
credential refusal with its hint and no attempt/workload; a capability refusal
is not a missing-source pass. No secret is passed in argv or printed.

Individual added lanes can be selected with `--case a01`, `--case small-task`
or `--case missing-source`. The default OAuth mode keeps the prior keychain/file
selection and expiry margin; an explicit OAuth source may instead be supplied.
An explicit source's expiry is not inferred from its bytes.

The new per-run compatibility checks require strict observation, all six active
classes without gaps, verified tree settlement and cleanup, one never-staged
vault credential, and agreement between text and JSON summaries. Exact use
counts require the guest's proxy journal; the host lifecycle journal is never
substituted for it. The harness independently reads the bounded exported
`guest-journal` manifest and exact part set, checks the raw receipt hash and
guest attempt identity, and verifies the complete journal's final canonical
settled receipt note. Links, oversized or changed reads, duplicate/foreign
events and sequence holes refuse. It counts credential-bearing proxy results
itself, checks the guest receipt's proxy count and use-recording note, and then
compares the tail's exact count. An old guest without that export, an explicit
unavailable state, or mismatched evidence cannot satisfy these conditions.

The whole matrix returns nonzero and can be only `FAIL` or `UNMEASURED` in this
implementation. The separate signed `9ceada861` installed-client synthetic
measurement demonstrates host-source revocation propagation, as recorded in
the [qualification ledger](../../../docs/benchmarks/jail/production-qualification-2026-11-15.md).
Vendor mid-stream revocation, full independent vendor-summary recomputation and
sampled environments remain outstanding, and the explicit workspace executable does not demonstrate
Linux alias-derived executable grants. Installed/notarized candidate acceptance
is separate. These limitations are retained in the report; synthetic tests do
not retire them or promote K108–K113.

```sh
cd crates/ukai-jail/vm
python3 -m unittest test_claude_vm_compatibility test_harness_rows.ClaudeRowTests -v
```

The separate `credential_revocation_measurement.py` uses a fresh **synthetic**
credential and an HTTP streaming peer on this Mac; it never reads a provider
source. Its normal mode runs the installed `ukai-jail run --vm --launch` path.
Only after the independent peer sees the substituted header and writes the
first response chunk does the harness delete its private source. A pass needs
a prompt upstream disconnect, the guest proxy's `credential_revoked` stream
end and later request refusal, no second upstream substitution, a bound complete
guest journal, exact receipt/tail use counts, verified enforcement and cleanup,
placeholder-only child output, and clean exported-file and same-boot disk scans.
The client capability refusal is retained when `credential_staging` remains
unmeasured. There is no automatic fallback.

```sh
python3 crates/ukai-jail/vm/credential_revocation_measurement.py \
  /path/to/installed-root /path/to/marked-workspace /path/to/new-evidence \
  /path/to/installed-root/bin/ukai-jail
```

An explicit `--raw-transport` flag selects a different development measurement
to establish the initial guest/service component evidence. It sends an exact
vault launch declaration and one synthetic `SecretEntry` directly to the warm
service, then sends `revoke_secrets` only after both the release frame and the
independent upstream acceptance. It requires the exact ID acknowledgement
within the service's two-second budget. It binds the guest receipt to the
request, guest and service boots, verifies exported journal bytes, and asks the
shipped binary to summarize a separate offline **guest** attempt. The report
retains the installed binaries' hashes, the image metadata and ready-frame
hashes, the declaration and argument digest. It does not manufacture a host
receipt, prove the host source watcher, or qualify the normal installed client.
The raw report uses a distinct schema and says `qualified=false`.

The raw display report is explicitly marked `display_redacted=true`. After
all synthetic-secret spellings have been scanned, it hash-binds separate exact
`raw-inputs.json` and `raw-launch.toml` files. The original guest and sync
receipts, guest journal parts and image metadata are retained beside them;
display address/path substitutions never change these replay inputs.
`credential_revocation_measurement.replay_raw(output_directory)` bounds and
verifies those files, rechecks the journal and receipt bindings, derives exact
credential counts and protocol acknowledgements, and recomputes the component
facts. It ignores stored `PASS`/`facts` and recomputes prior digest/header-match
flags. A complete persisted replay is required before the live raw report can
pass. Scan hit/count and peer timestamp/header-hash records are observations
captured on this host; offline replay does not re-attest the host or re-scan a
destroyed VM disk. Signed installed-package authority is independently checked
by the admission derivation, never inferred from the raw probe's verdict.

Both modes need a fresh guarded workspace, use only the explicitly granted
local plaintext endpoint, and retain failed conditions. Neither is a vendor
or TLS compatibility test, an automatic capability promotion, or K113 release
qualification. Run raw mode only on the intended current image; the old guest
cannot acknowledge this new revocation contract.

```sh
cd crates/ukai-jail/vm
python3 -m unittest test_credential_revocation_measurement \
  test_claude_vm_compatibility test_harness_rows.ClaudeRowTests -v
```
