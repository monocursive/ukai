# J14 persistent state: cost (K73) and the workspace check (K74), 2026-10-19

Rows K73 and K74 of [jail-interactive-sessions.md](../../specs/jail-interactive-sessions.md)
§6.2, measured on the reference host by the live tests in
`crates/ukai-jail/tests/j14_state_linux.rs`
(`k73_acquisition_and_release_cost_on_this_host`,
`k74_a_workspace_made_again_refuses_unless_its_inode_was_reused`), run the way
the conformance driver runs the suite: a user scope, `UKAI_CONFORMANCE=1`, a
scrubbed `PATH`, one test thread, release build, from the tree committed
with this record.

## Host

The reference VPS: Ubuntu 26.04.1, kernel 7.0.0-31-generic, x86_64 KVM, 4
vCPUs, 3 GiB of memory. The data directory and the state lived on `/tmp`
(tmpfs); the K74 workspace on the home directory's ext4. A real state lives
in the data directory, normally on disk, so these times are for a state in
memory: a pass that must read a cold state from disk is not measured here
and costs more by the disk's read time for the bytes listed.

## K73: acquisition and release

Each run is `ukai-jail run --launch keeper -- /usr/bin/true` under `agent`,
with one vault credential loaded (never sent), so every release runs the
secret scan. A run pays two full passes over the state: the acquisition's
digest, and the release's digest with the scan. The operator (the test)
wrote the state between runs; the first run after each write reports the
change, the second runs on a state unchanged since its release. Times are
the whole run, from the jail's start to its exit, as the test measured them.

| State | Run after the write | Second run | `matches_release` (first, second) | Scan |
|---|---|---|---|---|
| empty (first run creates it) | 69 ms | 68 ms | `null` (`new_state`), `true` | clean |
| 1 MiB, 16 files | 70 ms | 78 ms | `false`, `true` | clean |
| 64 MiB, 64 files | 400 ms | 411 ms | `false`, `true` | clean |
| 256 MiB, 256 files (the byte bound) | 1,417 ms | 1,446 ms | `false`, `true` | clean |
| 65,536 entries, 16-byte files (the entry bound) | 1,315 ms | 1,280 ms | `false`, `true` | clean |
| 257 MiB | 1,452 ms | 1,450 ms | `null` (`state_too_large`) both | `not_scanned` |
| 65,537 entries and more | 1,259 ms | 1,226 ms | `null` (`state_too_large`) both | `not_scanned` |

At either bound a run costs about 1.4 s more than an empty state, so one
pass costs about 0.7 s: well inside the 30-second preparation budget, which
holds the acquisition's pass. The full pass is kept; the incremental
manifest stays a candidate nobody needs yet (§4.6). The secret scan is no
measurable addition to the digest's own read, so its cost clears K73; it
stays a candidate for what it cannot find (encoded, compressed or split
copies, §4.5) and because past either bound it does not run at all
(`not_scanned`, a named limit in operating.md).

## K74: a workspace made again

- Removed, then made again at the same path after another directory took
  the freed inode: the next run refused `state_workspace_changed` before
  exec, naming `ukai-jail state rm`.
- Removed and made again at once: ext4 gave the new directory the old
  inode number (`inode_reused: true`), the check could not tell, and the
  run acquired the old state (exit 0). This is the named limit of §4.3,
  now measured rather than remembered.
